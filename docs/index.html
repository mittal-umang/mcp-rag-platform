Architecture

A source-based pipeline builds the corpus; the agent retrieves and grounds answers; the MCP server exposes tools to a host like Claude Desktop. Everything runs containerized on Kubernetes with GitOps and metrics.

What's inside

Hybrid retrieval

Dense + BM25 sparse, fused server-side with Reciprocal Rank Fusion via Qdrant's Query API. Optional cross-encoder reranker for higher precision.

Grounded answers, with a guardrail

Answers cite their sources. When the strongest match is below threshold, the agent refuses instead of hallucinating.

Data ingestion pipeline

Async batched fetch over the MediaWiki API with incremental re-index — a page is re-embedded only when its revision changes.

MCP server

Three tools — retrieve, fetch_source, ingest — over stdio for any MCP host.

Serving platform

Docker, a Helm chart, ArgoCD (GitOps) on a kind cluster, Prometheus /metrics and structured logs.

Pluggable + right-sized

Providers and sources selected by enum + registry. vLLM self-hosting wired for a Phase 2; ingestion is a batch job, not Spark, on purpose.

Quickstart

cp .env.example .env          # add your provider API key
make up                       # docker compose: agent + qdrant
python -m src.ingestion       # build the corpus (Wikipedia, incremental)
make ask Q="what is the capital of Japan?"

Retrieval defaults to hybrid. Deploy to a local cluster with make kind-up && make deploy && make argocd.

MCP tools

  • retrieve(query, k) — ranked chunks (dense or hybrid) with source citations
  • fetch_source(doc_id, section?) — the full document behind a chunk
  • ingest(source_uri | text, metadata) — add or re-index one document, idempotent per doc_id
